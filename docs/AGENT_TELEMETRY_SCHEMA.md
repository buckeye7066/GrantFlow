# Agent Telemetry Schema

Canonical schema for the unified telemetry tables that back the
**Agent Mission Control** dashboard
(`src/components/admin/AdminAgentMissionControl.jsx`).

These tables are created by:

- `backend/db/migrations/084_agent_telemetry.sql` (SQLite)
- `backend/db/postgres/migrations/0080_agent_telemetry.sql` (Postgres)
- and re-declared in `backend/db/schema.sql` for fresh-install bootstrap.

All migrations are idempotent. The aggregator at
`backend/services/agentTelemetry/agentTelemetryAggregator.js` reads from
these tables first; per-agent tables are read only when present.

---

## `agent_activity_events`

Append-only event log shared by every agent. Designed to be cheap to
write from agent code (a single insert per event) and cheap to query
for the dashboard.

| Column | Type (sqlite / pg) | Notes |
|---|---|---|
| `id` | TEXT PK | autogenerated UUID-ish |
| `agent_name` | TEXT | one of `anya`, `sam`, `robert`, `yana`, `john` (also `runtime` reserved for the always-on runtime) |
| `event_type` | TEXT | freeform — see "Event types" below |
| `status` | TEXT | one of `queued`, `running`, `succeeded`, `failed`, `blocked`, `warning`, `info` |
| `severity` | TEXT | one of `critical`, `high`, `medium`, `low`, `info` |
| `title` | TEXT | short, one-line summary surfaced on the timeline |
| `description` | TEXT | optional second line |
| `metric_key` | TEXT | optional — e.g. `leads_qualified`, `drafts_created`, `opportunities_ingested` |
| `metric_value` | REAL / DOUBLE | optional |
| `entity_type`, `entity_id` | TEXT | foreign-key-ish reference to the domain object touched (`opportunity`, `lead`, `email_draft`, `finding`, …) |
| `user_id`, `profile_id`, `organization_id` | TEXT | optional context |
| `state`, `county`, `city` | TEXT | optional geography (state stored upper-case on read) |
| `latitude`, `longitude` | REAL / DOUBLE | optional geography |
| `details_json` | TEXT (JSON) / JSONB | freeform extra detail; redacted server-side before responding |
| `created_at` | DATETIME / TIMESTAMPTZ | defaults to now |

Indexes (created by the migration):

- `idx_agent_events_agent_created (agent_name, created_at DESC)`
- `idx_agent_events_status_created (status, created_at DESC)`
- `idx_agent_events_event_type (event_type)` — sqlite only (pg matches)
- `idx_agent_events_state (state)`

## `agent_daily_rollups`

Daily counters per agent + metric. Useful for trend lines and for
Mission Control's day-over-day charts. Aggregator code can choose
between reading from this table or computing on-the-fly from raw
events; the rollup table exists primarily so future work doesn't have
to scan millions of events for a single dashboard render.

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | autogenerated |
| `agent_name` | TEXT | one of the canonical agent names |
| `rollup_date` | TEXT (sqlite) / DATE (pg) | `YYYY-MM-DD` |
| `metric_key` | TEXT | e.g. `leads_qualified`, `drafts_created` |
| `metric_value` | REAL / DOUBLE | running total for the day |
| `details_json` | TEXT / JSONB | optional |
| `created_at`, `updated_at` | DATETIME / TIMESTAMPTZ | timestamps |

Unique constraint: `(agent_name, rollup_date, metric_key)`.

`incrementDailyRollup(db, { agent_name, metric_key, metric_value })`
performs an idempotent upsert that adds to the existing value.

## Status values

| Value | Meaning |
|---|---|
| `queued` | Run has been requested but not started |
| `running` | Run is in flight |
| `succeeded` | Run completed without error |
| `failed` | Run threw / returned a non-success result |
| `blocked` | Action could not proceed (e.g. suppression hit, alias unverified) |
| `warning` | Completed but with quality / quota concerns |
| `info` | Pure informational signal, not a run |

## Severity values

| Severity | Use case |
|---|---|
| `critical` | Compliance break, security issue, product down |
| `high` | Schedule miss, repeated failure, ingestion regression |
| `medium` | Single failure, quality dip |
| `low` | Cosmetic / soft warning |
| `info` | Successful events; default for most timeline entries |

## Event types

Agents are encouraged to use stable `event_type` strings so the
dashboard can group and label them. The set is open, but Mission
Control already understands these:

| `event_type` | Producer | Notes |
|---|---|---|
| `run_completed` | any | summary record at end of a successful run |
| `run_failed` | any | summary record at end of a failed run |
| `agent_run` | any | generic per-run record (used by `countEventsByAgent`) |
| `draft_created` | john | one Outlook draft created |
| `draft_blocked` | john | one draft suppressed / refused |
| `lead_qualified` | yana | one lead promoted to qualified |
| `lead_rejected` | yana | one candidate rejected |
| `opportunity_ingested` | robert | one funding opportunity ingested |
| `opportunity_verified` | robert | one candidate marked verified |
| `error_found` | sam | one new finding |
| `error_resolved` | sam | one finding resolved |
| `gate_failed` | sam | a release gate failed |
| `session_started` | anya | a new chat session opened |
| `tool_invoked` | anya | a tool was called inside a session |

The synthetic timeline fallback uses `draft_created`, `draft_blocked`,
`tool_invoked`, and `session_message` for older deployments that have
not yet started writing unified events.

## Metric keys

Stable metric keys used in `metric_key` and in `agent_daily_rollups`:

| `metric_key` | Agent | Meaning |
|---|---|---|
| `websites_checked` | yana | URLs Yana fetched |
| `leads_found` | yana | candidate leads discovered |
| `leads_qualified` | yana | candidates promoted to qualified |
| `leads_sent_to_john` | yana | qualified leads queued to John |
| `drafts_created` | john | drafts created (counts toward 50/24h cap) |
| `drafts_blocked` | john | drafts refused for any reason |
| `suppression_hits` | john | drafts blocked by the suppression list |
| `opportunities_found` | robert | candidates discovered |
| `opportunities_verified` | robert | candidates marked verified |
| `opportunities_ingested` | robert | candidates ingested into general resources |
| `recommendations_created` | robert | profile recommendations |
| `recommendations_accepted` | robert | recommendations accepted into a profile pipeline |
| `checks_run` | sam | production readiness checks executed |
| `errors_found` | sam | findings created (severity ≥ low) |
| `errors_resolved` | sam | findings resolved |
| `failed_gates` | sam | release-gate failures |
| `interactions` | anya | message-level interactions |
| `tool_invocations` | anya | tool-usage records |

## Examples

### A successful Yana run

```json
{
  "agent_name": "yana",
  "event_type": "run_completed",
  "status": "succeeded",
  "severity": "info",
  "title": "Yana checked 42 pages, qualified 12 leads",
  "metric_key": "leads_qualified",
  "metric_value": 12,
  "details_json": {
    "urls_fetched": 42,
    "qualified": 12,
    "rejected": 18,
    "elapsed_ms": 178000
  }
}
```

### A John draft blocked by suppression

```json
{
  "agent_name": "john",
  "event_type": "draft_blocked",
  "status": "blocked",
  "severity": "medium",
  "title": "Draft blocked: recipient on suppression list",
  "entity_type": "lead",
  "entity_id": "lead_12345",
  "details_json": {
    "block_reason": "suppressed",
    "lead_id": "lead_12345"
  }
}
```

### A Sam critical finding

```json
{
  "agent_name": "sam",
  "event_type": "error_found",
  "status": "warning",
  "severity": "critical",
  "title": "Profile-scope guard tripped on /api/grants",
  "entity_type": "route",
  "entity_id": "/api/grants",
  "details_json": {
    "file_path": "backend/routes/grants.js",
    "rule": "PROFILE_SCOPE_VIOLATION"
  }
}
```

`details_json.password`-style keys are stripped to `[REDACTED]` before
the response leaves the server.

### A Robert opportunity ingestion (with geography)

```json
{
  "agent_name": "robert",
  "event_type": "opportunity_ingested",
  "status": "succeeded",
  "severity": "info",
  "title": "Ingested OH state firefighter grant",
  "entity_type": "opportunity",
  "entity_id": "opp_98765",
  "state": "OH",
  "city": "Columbus",
  "latitude": 39.9612,
  "longitude": -82.9988,
  "details_json": { "category": "fire", "source": "ohio.gov" }
}
```

### A daily rollup row

```json
{
  "agent_name": "yana",
  "rollup_date": "2026-06-15",
  "metric_key": "leads_qualified",
  "metric_value": 47
}
```
